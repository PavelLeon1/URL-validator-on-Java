# Валидатор URL-адресов

Консольное Java-приложение для проверки доступности URL-адресов из файла. Проект разработан в рамках лабораторной работы по курсу "Инструменты поддержки промышленной разработки программного обеспечения" (ИППРПО).

Приложение читает список URL, отправляет HTTP-запросы для проверки их доступности и выводит в консоль сгруппированный отчет о "живых" и "мертвых" ссылках.

## Технологический стек

*   **Java**: Язык программирования. Код написан с использованием возможностей JDK 21.
*   **Gradle**: Система автоматической сборки проекта.
*   **JUnit 5**: Фреймворк для модульного тестирования.
*   **Checkstyle**: Инструмент для статического анализа кода.
*   **GitHub Actions**: Система для автоматизации CI/CD (сборка, тестирование, анализ).

## Требования для запуска

*   **Git**: Для клонирования репозитория.
*   **Java Development Kit (JDK)**: **Версия 21**.
    *   Проект использует для компиляции возможности Java 21. Если у вас установлена другая версия JDK (например, 17 или 18), потребуется внести одно изменение в конфигурацию сборки (см. ниже).
    *   Минимально возможная версия для запуска — JDK 16.

## Установка и настройка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <URL-вашего-репозитория>
    cd <папка-проекта>
    ```

2.  **(Опционально) Настройка версии Java, если у вас не JDK 21:**

    Если у вас установлена другая версия JDK (например, 17), откройте файл `build.gradle` и измените версию в блоке `toolchain`.

    *   Найдите этот блок в `build.gradle`:
        ```groovy
        java {
            toolchain {
                languageVersion = JavaLanguageVersion.of(21)
            }
        }
        ```
    *   Замените `21` на номер вашей версии. Например, для JDK 17:
        ```groovy
        java {
            toolchain {
                languageVersion = JavaLanguageVersion.of(17)
            }
        }
        ```

3.  **Создайте файлы конфигурации:**

    > **Важно!** Файл `app.properties`  не отслеживаются системой контроля версий (добавлен в `.gitignore`) и должен быть создан вручную.
    

4. **Создайте файл `src/main/resources/app.properties`** со следующим содержимым:
        
        # Путь к файлу с URL-адресами внутри папки resources
        urls.file.path=urls.txt

        # Таймаут HTTP запроса (в миллисекундах)
        http.timeout.ms=5000

        # Метод запроса: HEAD или GET
        http.method=HEAD
        

## Сборка и запуск

Проект использует плагин `application` и Gradle Wrapper, что делает его запуск очень простым. Вам не нужно устанавливать Gradle глобально.

1.  **Сборка и анализ (рекомендуется):**

    Эта команда скомпилирует исходный код, запустит все тесты и выполнит проверку стиля кода с помощью Checkstyle.

    *   Для Linux / macOS:
        ```bash
        ./gradlew build
        ```
    *   Для Windows:
        ```bash
        gradlew.bat build
        ```

2.  **Запуск приложения:**

    Эта команда запустит приложение напрямую, без необходимости вручную собирать JAR-файл.

    *   Для Linux / macOS:
        ```bash
        ./gradlew run
        ```
    *   Для Windows:
        ```bash
        gradlew.bat run
        ```

## CI/CD Pipeline

Проект использует **GitHub Actions** для автоматизации процессов сборки и тестирования. Рабочий процесс настроен в файле `.github/workflows/ci.yml` и запускается при каждом `push` в основную ветку и при создании Pull Request.

**Основные этапы CI/CD:**
1.  **Создание конфигурации**: Файлы `app.properties` и `urls.txt` генерируются "на лету".
2.  **Статический анализ**: Запускается `checkstyleMain` для проверки кода.
3.  **Матричная сборка**: Проект собирается и тестируется на нескольких версиях Java (JDK 11, 17, 21) в среде Linux.

> **Примечание о среде сборки:** Gradle `toolchain` позволяет успешно собирать проект, написанный для Java 21, даже в окружении с более старой версией JDK (например, 11), так как Gradle автоматически скачивает нужную версию. Это стабильно работает в Linux-окружении, используемом в GitHub Actions.
