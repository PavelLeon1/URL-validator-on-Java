# Валидатор URL-адресов

[![Java CI with Gradle](https://github.com/PavelLeon1/URL-validator-on-Java/actions/workflows/ci.yml/badge.svg)](https://github.com/PavelLeon1/URL-validator-on-Java/actions/workflows/ci.yml)

Консольное Java-приложение для проверки доступности URL-адресов из файла. Проект разработан в рамках лабораторной работы по курсу "Инструменты поддержки промышленной разработки программного обеспечения" (ИППРПО).

Приложение читает список URL, отправляет HTTP-запросы для проверки их доступности и выводит в консоль сгруппированный отчет о "живых" и "мертвых" ссылках.

## Основной функционал

*   **Чтение URL из файла**: Путь к файлу со списком URL-адресов задается в конфигурационном файле.
*   **Проверка доступности**: Для каждого URL отправляется HTTP-запрос (метод HEAD или GET настраивается).
*   **Классификация ответов**: Результат каждого запроса классифицируется по статусу:
    *   `OK` (коды 2xx)
    *   `REDIRECTION` (коды 3xx)
    *   `CLIENT_ERROR` (коды 4xx)
    *   `SERVER_ERROR` (коды 5xx)
    *   `TIMEOUT` (если запрос превысил заданный таймаут)
*   **Генерация отчета**: В консоль выводится отчет, сгруппированный по статусам, с отдельными списками для проблемных и рабочих URL.

## Технологический стек

*   **Java 21**: Язык программирования.
*   **Gradle**: Система автоматической сборки проекта.

## Установка и настройка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <URL-вашего-репозитория>
    cd <папка-проекта>
    ```

2.  **Создайте файлы конфигурации:**

    > **Важно!** Файлы конфигурации `app.properties` и `urls.txt` не отслеживаются системой контроля версий (добавлены в `.gitignore`) и должны быть созданы вручную для локального запуска.

    *   **Создайте директорию для ресурсов:**
        ```bash
        mkdir -p src/main/resources
        ```

    *   **Создайте файл `src/main/resources/app.properties`** со следующим содержимым:
        ```properties
        # Путь к файлу с URL-адресами внутри папки resources
        urls.file.path=urls.txt

        # Таймаут HTTP запроса (в миллисекундах)
        http.timeout.ms=5000

        # Метод запроса: HEAD или GET
        http.method=HEAD
        ```

    *   **Создайте файл `src/main/resources/urls.txt`** и добавьте в него список URL для проверки (каждый URL с новой строки):
        ```
        https://google.com
        https://github.com
        https://google.com/no-such-page-404
        https://httpstat.us/503
        https://httpstat.us/301
        ```

## Сборка и запуск

Проект использует Gradle Wrapper, поэтому вам не нужно устанавливать Gradle глобально. Все команды выполняются из корневой папки проекта.

1.  **Сборка проекта:**

    Эта команда скомпилирует исходный код, запустит тесты, выполнит проверку Checkstyle и соберет исполняемый JAR-файл.

    *   Для Linux / macOS:
        ```bash
        ./gradlew build
        ```
    *   Для Windows:
        ```bash
        gradlew.bat build
        ```
    Готовый JAR-файл будет находиться в директории `build/libs/`.

2.  **Запуск приложения:**

    После успешной сборки запустите приложение с помощью следующей команды:

    ```bash
    java -jar build/libs/<имя-вашего-jar-файла>.jar
    ```
    *(Например, `java -jar build/libs/url-validator-1.0-SNAPSHOT.jar`)*

### Пример вывода в консоль
    ```
    Starting URL validation...
    --- FAILED URLS ---
    [CLIENT_ERROR: 404] https://google.com/no-such-page-404
    [SERVER_ERROR: 503] https://httpstat.us/503
    --- OK URLS ---
    [OK: 200] https://google.com
    [OK: 200] https://github.com
    [REDIRECTION: 301] https://httpstat.us/301
    Validation finished.
    ```
## CI/CD Pipeline

Проект использует **GitHub Actions** для автоматизации процессов сборки и тестирования. Рабочий процесс настроен в файле `.github/workflows/ci.yml` и запускается при каждом `push` в репозиторий.

**Основные этапы CI/CD:**

1.  **Создание конфигурации**: Файлы `app.properties` и `urls.txt` генерируются "на лету" во время выполнения workflow.
2.  **Статический анализ**: Запускается `checkstyleMain` для проверки кода на соответствие стандартам (включая наличие JavaDoc у публичных методов). Сборка прерывается при ошибках.
3.  **Матричная сборка**: Проект собирается и тестируется на нескольких версиях Java (JDK 11, 17, 21) для обеспечения совместимости.
